> **导读**：随着大语言模型的能力持续演进，提示词工程的重点也在变化。过去为了约束旧模型而堆叠的大量流程化指令，在 GPT-5.5 这类更擅长推理与遵循目标的新模型面前，可能反而会变成干扰信号。更好的方向，是从"手把手指挥"转向"目标驱动的授权"：把成功标准、约束和停机条件讲清楚，让模型自己选择最经济的解决路径。

---

## 背景：提示词工程正在发生范式转移

OpenAI 官方提示词指南强调，最新模型在推理效率、指令遵循和工具协作上都有明显提升。这意味着，提示词不再需要承担所有过程控制职责。

过去常见的做法，是在 Prompt 里写满"第一步做什么、第二步检查什么、第三步调用哪个工具"。这种方式在旧模型上可以降低失控概率，但也会把模型锁死在固定路径里，削弱它根据上下文自主判断的能力。

在 GPT-5.5 时代，更值得采用的是 **Outcome-first（结果第一）** 的思路：

- 先定义最终要交付的结果；
- 再定义成功标准和必要约束；
- 最后给出明确的停机规则；
- 具体路径尽量交给模型根据上下文决定。

简单说，提示词的重心应该从"规定路线"转向"定义终点"。

## 一、核心转变：从过程导向到结果导向

相比更早版本的模型，GPT-5.5 展现出更强的自主推理与任务规划能力。提示词工程因此需要少一些机械流程，多一些清晰目标。

### 1. 精简提示词

短小、明确、面向结果的提示词，往往比冗长的流程堆叠更有效。

真正重要的不是把每个动作都写死，而是告诉模型：

- 什么是好的最终答案；
- 哪些约束不能违反；
- 哪些信息可以作为证据；
- 什么时候应该停止继续搜索或推理。

### 2. 重新评估推理成本

模型能力提升之后，不是每个任务都需要直接推到 `high` reasoning effort。

实践中可以先从 `low` 或 `medium` 开始评估。如果任务已经能稳定产出足够好的结果，就没有必要用更高的推理成本换取有限收益。

更高努力值适合复杂规划、多源证据整合、高风险判断等任务；常规改写、摘要、格式整理和轻量分析，通常不需要一开始就拉满。

### 3. 给模型留出自主空间

好的提示词应该像给一位成熟合作者交代任务，而不是像写脚本一样逐行控制。

你可以清楚说明：

- 目标是什么；
- 质量标准是什么；
- 可用证据在哪里；
- 哪些行为被禁止；
- 什么时候必须向用户追问。

在这些边界之内，具体采用什么策略、是否调用工具、先处理哪个子问题，可以让模型根据当前上下文动态选择。

## 二、四个核心策略

### 策略一：结果导向，并设置明确停机条件

很多旧 Prompt 喜欢大量使用 `ALWAYS`、`NEVER`，或者强行规定"先检查 A，再检查 B，然后对比字段，最后解释全过程"。除非涉及安全、法律、权限或严格输出格式，这种硬编码流程通常会降低模型的灵活性。

更好的写法，是定义成功标准和停机条件。

**反面示例：过度过程控制**

```text
先检查 A，再检查 B，然后对比所有字段，思考所有可能的例外情况，
接着决定调用哪个工具，最后向用户解释整个过程。
```

**正面示例：结果导向 + 停机条件**

```text
端到端地解决客户问题。

成功标准：基于现有政策和账户数据做出资格审查决定；
在响应前完成所有允许的操作。

停机规则：在每轮结果后思考：
"我现在能否用有力的证据和引用直接回答用户的核心问题？"
如果可以，立即回答并停止。
```

这个版本没有剥夺模型的判断空间，但明确告诉它什么叫完成、什么时候停止。

### 策略二：用前导语改善流式响应体验

在复杂 Agent 工作流中，模型可能需要先规划、检索、调用工具或读取上下文。对用户来说，如果流式响应迟迟没有首字输出，就会产生"系统卡住了"的感觉。

可以在系统提示词中要求模型在执行工具调用或深度分析前，先输出 1-2 句自然的前导语：

```text
在进行工具调用或多步骤分析前，先用 1-2 句话说明你将要做什么。
前导语应简短、具体，不要复述整段用户请求。
```

例如：

```text
我会先核对现有账户信息和适用政策，然后判断是否已经足以给出资格结论。
```

这类前导语不会改变任务本身，却能显著改善用户对响应速度和过程透明度的感知。

### 策略三：为检索设定预算

Agent 很容易在外部知识库或网络搜索中陷入"再搜一次"的循环。为避免检索失控，需要给 Prompt 设定明确的 Retrieval Budget。

一个实用的默认规则是：

- 先进行一次宽泛关键词搜索；
- 如果首批结果已经足以回答核心问题，立即作答；
- 只有在关键信息缺失时才继续检索；
- 用户要求穷尽式对比时，才扩大检索范围；
- 高风险文档、具体政策、日期或 ID 不明确时，可以追加检索。

示例：

```text
默认最多进行一次宽泛检索。
只有在核心问题仍未解决、缺少关键事实/日期/ID、
用户明确要求穷尽式对比，或必须阅读特定高风险文档时，才允许再次检索。
一旦证据足以支持核心回答，立即停止检索并作答。
```

检索预算的价值在于，它既保证事实可靠性，也避免 Agent 把时间和成本消耗在边际收益很低的搜索上。

### 策略四：区分事实驱动与创意草拟

文案、幻灯片、领导讲话稿、产品方案这类任务，往往同时包含事实与创意。最容易出问题的地方，是模型把创意能力误用在事实细节上。

因此，Prompt 中应该明确划分边界：

| 内容类型 | 处理原则 |
| --- | --- |
| 产品指标、客户数据、路线图、功能状态 | 必须完全基于真实素材或检索结果 |
| 日期、金额、名称、版本号、政策条款 | 必须有证据支撑 |
| 标题、叙事结构、语气、表达方式 | 可以创造性优化 |
| 缺失的事实信息 | 使用占位符或明确标注假设 |

示例：

```text
事实类内容必须完全基于提供材料或检索结果。
如果缺少产品名称、客户数据、时间线或指标，不要编造；
使用 [待补充] 占位符，并在结尾列出需要用户确认的信息。
表达风格、结构和过渡语可以自由优化。
```

这条规则可以显著降低"看起来很专业，但具体信息是编的"这类风险。

## 三、生产级 Prompt 的推荐结构

复杂任务不需要无限加长 Prompt，但需要结构清楚。一个稳定的生产级模板可以这样组织：

```text
Role:
[用 1-2 句话定义模型的角色、上下文和具体职责]

# Personality
[设定模型的语气、举止以及与用户的协作风格]

# Goal
[最终的用户可见成果]

# Success Criteria
[在给出最终答案之前，必须满足的硬性条件]

# Constraints
[政策、安全、商业逻辑、证据限制以及副作用限制]

# Output
[输出结构、篇幅长短和整体基调]

# Stop Rules
[何时重试、何时启用后备方案、何时主动询问用户、何时停止]
```

关键不是每次都机械填满所有区块，而是只保留真正会影响模型行为的内容。

如果某个约束不会改变模型选择，就不必写；如果某个成功标准决定了是否能交付，就必须写清楚。

## 四、从旧 Prompt 到新 Prompt 的重构思路

旧模型时代的 Prompt 往往像一套防御工事：规则密、流程长、异常分支多。迁移到 GPT-5.5 时，可以按下面的方式重构。

| 旧模型思维 | GPT-5.5 新思维 |
| --- | --- |
| 手把手指定每一步操作 | 定义目标与停机条件 |
| 越详细越好 | 精简，只保留真正影响行为的约束 |
| 堆叠流程化指令 | 结果导向，给模型自主空间 |
| 忽略推理成本 | 优先评估 `low` / `medium`，按需升级 |
| 无限制检索 | 设定检索预算，避免反复搜索 |

一个简单的重构方法是，逐段审查现有 Prompt：

1. 这句话是否定义了结果、约束或质量标准？
2. 如果删除它，模型行为是否真的会变差？
3. 它是在帮助模型判断，还是在强迫模型执行某条固定路线？
4. 是否可以改写成成功标准或停机条件？

经过这一步，很多旧 Prompt 都能压缩到原来的三分之一甚至更短，同时保留更强的泛化能力。

## 五、总结

GPT-5.5 的进化，让提示词工程离"表达意图，而不是指挥过程"更近了一步。

面向新模型，值得长期保留的不是复杂流程本身，而是这些更稳定的原则：

- 用结果定义任务，而不是用步骤框死任务；
- 用成功标准描述质量，而不是用冗长说明堆叠控制感；
- 用停机条件控制成本和节奏；
- 用检索预算防止 Agent 过度搜索；
- 用事实边界防止创意任务中的具体信息幻觉。

如果你手头还有大量为旧模型写下的提示词，现在正是用 Outcome-first 的方式做一次精简重构的好时机。
