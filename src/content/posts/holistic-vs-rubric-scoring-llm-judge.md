> **导读**：让模型给一段回答打分，可以看完直接给一个总分（holistic scoring），也可以先把评分标准拆成若干检查项，逐项判定后再汇总。从近三年的论文看，后一种做法和人类专家的一致性更高，多次打分的波动也更小。但带来提升的是“针对每道题拆出来的是非题”，多维度的 1–5 分量表做不到这一点；拆得不好时，结果还会比直接打总分更差。

---

## 一、两种做法各是什么

**整体打分**：把题目和回答交给评委模型，要求输出一个分数，比如 1–10 分。提示词里通常只有一句笼统的标准，如“评估这个回答的质量”。

**先拆 Rubric 再打分**：先把“质量”拆成若干条可以单独核对的检查项，评委模型逐条判定，总分由这些判定汇总得到。

整体打分的问题在于，事实是否正确、指令有没有遵守、行文是否通顺、格式是否符合要求，这几件事经常互相冲突，模型却要把它们压成一个数。各维度怎么折算，模型每次都是临时决定的，所以同一个回答多打几次，或者提示词换个说法，分数就会变。

## 二、支持“拆开打分”的论文

### 2.1 第一步：让评委先把评估步骤写出来

**G-Eval**（EMNLP 2023，[arXiv:2303.16634](https://arxiv.org/abs/2303.16634)）让模型先根据评测目标生成一份评估步骤，再按步骤填表打分，最后用输出 token 的概率对分数加权。在摘要和对话任务上，它与人类评分的相关性超过了此前的自动指标。

**FLASK**（ICLR 2024，[arXiv:2307.10928](https://arxiv.org/abs/2307.10928)）把“整体质量”拆成 4 类能力、12 项细粒度技能，并给每条测试指令标注它实际考察的那几项技能，评委只在这几项上打分。论文报告的结果是，这样做比不分技能的打分更接近人类评估，而且能看出模型具体差在哪项技能上。

**Branch-Solve-Merge**（NAACL 2024，[arXiv:2310.15123](https://arxiv.org/abs/2310.15123)）把评估任务拆成几个子维度，各自独立打分后再合并。它针对的是约束很多的题目：评委一次看全部要求时容易漏掉其中几条，分开判则不会。

**Prometheus**（ICLR 2024，[arXiv:2310.08491](https://arxiv.org/abs/2310.08491)）和 **Prometheus 2**（EMNLP 2024，[arXiv:2405.01535](https://arxiv.org/abs/2405.01535)）的做法是把评分标准显式写进输入，1–5 分每一档对应什么表现都写清楚。在这种输入下，13B 的开源模型和人类评分的相关性已经与 GPT-4 相当。

### 2.2 第二步：从量表改成是非题

上面几篇用的仍然是 1–5 分这类刻度。后来的工作发现，模型区分 3 分和 4 分时噪声很大，而回答“是否包含三个例子”这类是非题时要可靠得多。

**InFoBench**（[arXiv:2401.03601](https://arxiv.org/abs/2401.03601)）把每条指令拆成若干个是非题，例如“是否给出了三个例子”“是否避免了专业术语”，用回答满足的比例作为得分，论文称之为 DRFR（Decomposed Requirements Following Ratio）。和直接打总分相比，拆成是非题后，标注者之间的一致性更高。

**CheckEval**（EMNLP 2025，[arXiv:2403.18771](https://arxiv.org/abs/2403.18771)）把同样的思路用到文本生成评估上：把评估维度展开成一份布尔检查表，逐项回答是或否。论文报告了两项改进，一是与人类评分的相关性更高，二是不同评委模型之间的一致性更高。

### 2.3 第三步：每道题一份自己的检查表

再往后，检查表不再是整个数据集共用一份，而是每道题单独一份。

**WildBench**（[arXiv:2406.04770](https://arxiv.org/abs/2406.04770)）的题目来自真实用户对话，每道题都配了一份专属的检查清单，评委对照清单评估。

**HealthBench**（OpenAI，[arXiv:2505.08775](https://arxiv.org/abs/2505.08775)）走得更远：5000 段医疗对话，每段都有医生专门为它写的评分条目，每条带一个分值，可以是负分，用来扣掉有害的内容。评委模型逐条判断回答是否满足，最后按分值汇总。

复杂的真实任务和医疗这类高风险领域，目前的评测大多采用这种“每题一份检查表”的做法。

## 三、拆开之后少了哪些偏差

**MT-Bench 论文**（NeurIPS 2023，[arXiv:2306.05685](https://arxiv.org/abs/2306.05685)）系统地记录过评委模型的几种偏差，其中位置偏差和冗长偏差在整体打分里最明显。拆成检查项之后，下面三种情况都会减轻：

- **偏爱长回答**。整体打分时，回答越长越容易拿高分。检查项只问某个信息点或约束有没有满足，多写的内容不会加分。
- **被排版影响**。列表、加粗用得多的回答看上去更专业，即使里面有事实错误，整体打分也常常给高分。只要检查表里有事实核对项，这类错误就会被单独判出来。
- **漏看要求**。提示词很长、要求很多时，整体打分往往只照顾到其中几条，靠后的几条尤其占便宜。显式列出清单后，每条约束都必须有一个判定。

## 四、三种拆了反而更差的情况

拆开打分并不是在所有情况下都更好。自动作文评分（AES）和心理测量方向的研究里，有三种情况反复出现，结果是汇总分与人类总分的相关性低于直接打总分。

### 4.1 把语法、拼写单独列成维度

在逻辑、内容相关性这类高阶维度上，模型逐项打分与人类很一致。但把语法、拼写、标点单独列成一个维度后，模型会比人类严格得多，一个小语病就给很低的分。人类评分者通常不会因为这类小问题大幅扣分。这时如果把各维度的分数直接相加，总分就会被这一项拉偏。

处理办法是不把这类低阶项单独列成一条，或者列出来但给很低的权重。

### 4.2 Rubric 写得太长

评分标准并不是越详细越好。大段散文式的描述会分散评委模型的注意力，各条之间有重叠时，同一个问题还会被重复扣分。效果最好的检查项有三个特点：短，彼此不重叠，每条只问一件可以回答是或否的事。

### 4.3 用算术平均汇总

人类给总分时，有些错误是一票否决的：代码跑不起来，或者医疗回答里有一处可能致命的错误，那么格式、语气、结构再好，总分也是最低档。

算术平均没有这个逻辑。假设拆了五个维度，事实正确性得 0 分，其余四项各得 5 分，平均下来是 4.0 分，而人类会给 1 分。

## 五、对比

| | 整体打分 | 先拆 Rubric 再打分 |
| --- | --- | --- |
| 与人类评分的一致性 | 中等，受长度、排版、位置影响 | 较高，用逐题的是非题清单时差距最大 |
| 多次打分的波动 | 大 | 小 |
| 能否定位失分点 | 不能 | 能，可以统计每个检查项的通过率 |
| token 成本与延迟 | 低 | 较高，检查表可以缓存来分摊 |
| 适合的任务 | 文风偏好等主观判断、大批量初筛 | 指令遵循、事实问答、代码和 Agent 评测、专业领域评测 |

## 六、落地：两阶段评估

综合上面的论文，一套可行的做法分两个阶段。

**阶段一：离线生成检查表。** 对测试集里的每道题（有参考答案的话一并输入），用能力强的模型生成 3–7 条互不重叠的是非题，并给每条标上权重，以及它是不是一票否决项。生成一次后存下来，后续评估直接复用。

**阶段二：在线判定，代码汇总。** 评委模型拿到待评回答后，对每条检查项先摘出一小段证据，再给出通过或不通过。需要中间档时可以用 0 / 1 / 2 三档，不建议超过五档。总分不让模型算，由代码按下面的规则算出：

```python
def aggregate(items, results, blocker_cap=0.2):
    """items: 检查项列表，含 weight 和 blocker；results: 每项是否通过。"""
    total = sum(item.weight for item in items)
    earned = sum(item.weight for item, ok in zip(items, results) if ok)
    score = earned / total

    # 任何一条一票否决项没通过，总分封顶
    if any(item.blocker and not ok for item, ok in zip(items, results)):
        score = min(score, blocker_cap)
    return score
```

这里有两点对应前面第四节的问题：一票否决项不通过时总分封顶，解决算术平均失真；求和放在代码里，是因为模型做加权求和本身会出错，没有必要让它来算。

如果检查项已经拆到每条只判一件事，评委模型还要不要开思考，是另一个问题，我在[上一篇文章](/blog/posts/atomic-rubric-scoring-turn-off-free-cot/)里单独讨论过。

## 七、小结

- 拆开打分比整体打分更接近人类判断，波动也更小，前提是拆出来的是针对每道题的是非题。
- 通用的多维 1–5 分量表改善有限，模型在相邻两档之间的区分并不稳定。
- 语法、拼写这类低阶项不要单独列成维度；检查项要短、不重叠；汇总时要有一票否决，并且放在代码里算。
- 纯主观的文风判断和大批量初筛，直接打总分仍然够用，成本也低得多。
